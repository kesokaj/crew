## 22. Testing

`make check` runs everything here that needs no microVM and no agent CLI. It exists from M1, the building agent runs it before every commit, and the gate later runs the same command (16.2). Neither styrman-crew nor styrman-harness has continuous integration, so this is the first. `make test-go-pkg PKG=./internal/<pkg>` runs and times one Go package in the check container, and `internal/httpapi`'s tests run in parallel where their state is their own (since 1.26, CREW-25).

| Level | What | How |
| --- | --- | --- |
| Backup and restore | A dump and the month files restore into an empty database, and a project comes back complete. After a restore every session and personal token is ended. | A scratch database, before every release |
| Network modes | A Model only sandbox reaches only the hosts on the list and resolves no other name. A LAN sandbox reaches the local network. No sandbox reaches the machine, a metadata address, or anything over IPv6. | Real containers, run on demand |
| Login lost and found | A run whose CLI loses its login keeps its work in progress, waits, and continues after the sign-in. A login file for another account is refused. A project terminal gets the login of every signed-in CLI, and a run of only one. `ANTHROPIC_API_KEY` is set in no sandbox. | `FakeHarness`, and one real run on demand |
| Restart | The server or the machine restarts in the middle of runs, an update, and a merge. Every run is taken over or continued, and nothing starts twice. | `FakeHarness` with a stopped server |
| Pull requests and outside work | A pull request is opened, marked merged, and closed. Work merged at GitHub outside Crew becomes the base and is checked. | A fake GitHub server |
| `judge:` checks and check errors | A judge's answer in the fixed form passes or fails. Anything else and a timeout are errors, tried again, and never a fix round. At a limit a judge moves to its second choice or waits, which is no error. | `FakeHarness` |
| The checks decide | A test entry written from inside the tester's sandbox does not move a ticket. The check sandbox's result does. | `FakeHarness` with a tester that lies |
| File rules | A push outside `may_change` is refused. A change to a hook, a settings file of a CLI, an MCP configuration, or a workflow waits for the operator. A judging run gets its instruction files from `main`. | Temporary repositories |
| Limits of a project | A project pauses when the tickets agents added pass their share of the plan's tickets. A replacement, a discarded ticket, and a ticket the operator made do not count. A project with no tickets from the plan has no scope guard. | Unit tests |
| After Done | A new ticket makes a finished project run again. Revert, archive, and delete, with the row that says a project was deleted. | Temporary repositories, a scratch database |
| Sessions and requests | A request from another site is refused. A fresh sign-in is asked for where 20.3 says. A device that was signed out is out. | Browser tests |
| The fake harness | `FakeHarness` plays a script: events in order, calls to the Crew MCP, commits and pushes, and stop reasons. So every path in 11.3 and 12.4 can be driven without a CLI. | Part of the test kit, built in M3 |
| The model for a run | For the model and for the effort: a pin on the ticket wins, then the project's setting, then the machine's entry, which is Crew's automatic choice or the operator's own. A release with other entries in its baseline changes none of them. Where each came from is recorded. Results are kept per role, kind of work, model, and effort. Lead slots are counted for each CLI, and a lead run waits for a slot of its own CLI. | Unit tests with scripted numbers |
| Credentials | A run gets the login of the one CLI it runs and a GitHub token that can only read, and no gcloud (since 0.79). It never gets the SSH key or the `gh` login. The token names only the project's repositories. The improver, a judge, a summary writer, and a prompt writer get only the login of their CLI. A conversation about a project gets what a run of that project gets, and about no project the login of its CLI and the git identity. The chat of a ticket gets only the login of its CLI and the read-only GitHub token. A check gets only the read-only GitHub token, and a hosted project none. A stored credential cannot be read without the key file. | Real containers, run on demand |
| Skills per project | A skill on `main` reaches the next run. A request becomes one ticket. A changed skill is not loaded by the run that judges the change. | Temporary repositories, `FakeHarness` |
| The kanban rule | No move ever takes a ticket to an earlier stage. A failed stage creates a fix subtask in place, and the stage checks again. | Plain tests over every row of the reconcile table |
| Unit | Fixed and optional stages, skipped stages, the why-what-goal rule, analysis decisions, subtasks, ticket links, limits, the merge queue, plan and task schemas, settings validation, watchdog rules | Plain tests, no git |
| Git store | Commits, trailers, merges, conflict paths, revert, and finishing a merge that a crash left half done | Temporary repositories |
| Database | Every change is one transaction with its row in `changes`. A job is taken once. The schema steps apply forward on a copy of the previous release's data. A project's rows are never returned for another project. Export and import give the same project back. A sandbox cannot connect. | A real PostgreSQL container |
| Git HTTP | A run token can read and push only what it is allowed to | Temporary repositories and tokens |
| GitHub client | Create, push, fetch, and error cases | A fake GitHub server, and one real test repository run on demand |
| Crew MCP | Every tool: what each role may call, and that a token of one project cannot reach another | Unit tests with tokens |
| Orchestrator | Every row of the reconcile table, the capacity check, and the lead queue in its order: class, the operator's priority across projects, the project's turn, the ticket's own priority, and age. A turn of a chat goes first in its class. A lead run waits for a slot of its own CLI. | `FakeHarness` with scripted events |
| Another installation | `crew-ctl release pull` and `release import` bring a release to a second machine. A release whose images do not match its hashes, or whose images are not the ones `release.json` names by their config, is refused. Every release waits for Install there. No improver runs, and no release is made. | `crew-ctl`'s and the updater's tests with files `docker save` wrote on both image stores; the install test's phase `second` on a fresh VM |
| Monitor and trajectories | Events are written in order, secrets are removed, replay matches, watchdog stops fire, every line of a spool becomes one row exactly once, also across a restart, and a run whose events cannot be written is stopped | `FakeHarness` with scripted stuck and silent runs |
| Conversations | The three ways to continue: a new call in the same sandbox, a new sandbox with the CLI's files put back from the database, and rebuilt from the turns. Which runs share a conversation. The tokens of a run on a continued conversation. | Recorded `events.jsonl` files of `agy`, and `agy` once on demand |
| Conversations with the operator | A turn is saved before the answer is shown. The sandbox is removed when idle and comes back. A conversation sees one project or none. It cannot push or move a ticket. A ticket it proposes is analysed like an agent's, and is the operator's when the operator makes it in the app. | `FakeHarness`, a scratch database; and `make test-talk` on demand: at most six real `agy` turns on a throwaway stack, where Crew starts no `agy` of its own (since 0.76) |
| The chat of a ticket | A question on a running ticket is answered by the assistant, and the working run gets nothing and does not stop. Tell the agent makes a comment that reaches the working run. On a Done ticket Tell the agent is not offered, and Make a ticket of this creates a linked ticket. Marked text arrives quoted with its source. An instruction inside a quote is not followed. The assistant cannot push, cannot move the ticket, and cannot read another ticket's chat or another project. Its token has no tool that writes. Its sandbox gets the login of its CLI and the read-only GitHub token, and no gcloud. A project agent cannot read a chat. A comment sent on with Tell the agent says that the assistant wrote it. A ticket made from a chat cannot skip Review. | `FakeHarness`, browser tests; two real questions in `make test-talk` (since 0.76) |
| Summaries | Facts match the records for a scripted task | Fixture records, with the model call faked |
| API and UI | Plan draft to project OK, board, inbox, the task view with agent, model, prompt, source plan, and subtasks, documentation, replay | `FakeHarness`, browser tests |
| Sandbox isolation | Two sandboxes cannot see each other. A sandbox reaches the internet but not the machine or the local network. | Real containers, run on demand |
| Prompt rewriting | The prompt writer's answer in its fixed form gives the rewrite, the changes, the assumptions, and the questions. Anything else, a timeout, and a limit with no next choice send the operator's own text. Use, Edit, Send mine, and Rewrite again each save both texts and the choice, and the planning agent gets only the chosen text. A rewrite in one project gets nothing of another. "Good as it is" sends without a stop. With `off` nothing is proposed, and the menu on a selection still works. Improve text replaces the selection only when the operator chooses Use it, and sends nothing. Review text changes nothing and gives at most five notes. On the plan of a draft both become a message to the planning agent with the selection quoted. A ticket the operator adds gets no proposal by itself. | `FakeHarness`, browser tests |
| Automatic choice of a model | With scripted numbers: no change below the minimum of runs, none where the difference is not clear, none that breaks the rule for checks, and at most one for an agent in 7 days. One run in ten of an automatic agent is a try, never on a pinned ticket or in a project that set the agent. After a change, worse numbers in the watched runs take it back, and that entry is not tried for 30 days. An agent that is Set by you is never changed, has no tries, and gets a recommendation. For an agent that checks, only fewer escaped defects with about as many fixes asked changes it, no rule uses a cost (since 0.53), and a model that asks for clearly fewer or clearly more fixes is not taken. A bug report that Analysis did not approve changes no numbers, and neither does the ticket a report names until the analysis of its fix ticket confirmed it (since 0.54). A setting under `agents.auto` cannot be changed by an improvement. Runs older than `window_days` are not counted. For the builder the counts are tickets, and a fix round never changes the entry. Go back restores the earlier entry. A release with new entries in its baseline changes no running entry. A patch of an improvement that touches a model, an effort, or the model line of an agent file is refused. A comparison sends every second run to the other entry, respects a pin, pauses while the other entry cannot run, and ends at its count. With `agents.auto.on` false, nothing changes without the operator. | Unit tests with scripted numbers |
| Crew level | Signals are recorded for scripted runs. A project token cannot reach Crew-level tools. The generic check refuses project names, paths, and copied text. Apply, measure, and roll back. | `FakeHarness` with two fixture projects |
| Prompts | The saved prompt equals the text the agent received, and can be rebuilt from the parts in the run record | `FakeHarness`, fixture baseline |
| Documentation | Indexing, the `docs_done` check, out-of-date marks, the changelog, and an operator edit | Temporary repositories |
| Run driver | The outputs of each CLI: a normal run, a refused tool, a quota stop, a missing login, a timeout | Recorded `events.jsonl` files of `agy` through its parser |
| Models | Reading recorded outputs of `agy models` into models, efforts, and families, with a name that was added. The three levels a model and an effort come from. The check rule, with and without another family. A model that is gone. A limit on one group, and a CLI that is signed out: a run moves to its next choice, a check never moves to the builder's family, and with `wait` nothing moves. | Recorded outputs, `FakeHarness` |
| Updater | A release that fails each step of the check, the switch, switching back in the watch time, roll back to a kept version, and a schema change tried on a copy | The updater against a scratch database and a second Docker daemon, never the real ones |
| Integration | A real run in a real microVM | The fixture project and each CLI once, on demand and before a release. This extends styrman-crew's integration suite. |
| Crew's own evals | A fixture project with a fixed eval suite | Track goals met, rework, tokens, and time per Crew release |
| Deciding | `decide` writes the decision and the memory entry in one transaction, and the run goes on. Changing a decision creates a ticket. | `FakeHarness` |
| Tickets that cannot get through | The fix-round limit and two stops queue the lead. The first look gives a new approach. The second cancels the ticket and creates its replacements, with their links and the dependencies moved over. A replacement is not replaced again. | `FakeHarness` with scripted failures |
| Notices | The 24 hours of a new feature and of a release: going ahead, Approve now, Discard, Hold, and Pause all | A fake clock |
| Parallel subtasks | The start order, pushes outside `touches` refused, the join, a conflict, and the join subtask | Temporary repositories |
| Notifications | One mail for what needs you, again after four hours, the daily mail of news, and that a link alone never decides | A fake mail server |
| Hosting | Build, start, health, switch, roll back with the data copy, the four access choices, the header removed from incoming requests, and no shared cookie | Real containers, run on demand |
| Personal tokens | Limited to their projects, "may answer", running out, the call limit, and refused from a sandbox | Unit tests with tokens |
| What installs by itself | A release that changes only prompts and harness text installs after its notice. A release that changes any other path waits, whatever an agent wrote about it. With `unprotected`, a release that touches each protected part waits. | The updater against a scratch database |
| Install, update, uninstall | On a fresh virtual machine: `doctor`, install from one file of answers, `crew-ctl selftest` with a ticket on the fixture project, `edit` of one value, a backup and its restore, update, roll back, uninstall at each level, install again after level 2 on the kept data, nothing left behind after level 3, and install again. A dry run changes nothing. | A fresh virtual machine with nested virtualization, before every release, unless `updates.install_test` is `off` (16.11). The same without root against a scratch folder, with `make check`, on every change. |
| Reproducible and clean | A build that changes a lock file fails. A place on the fixed list that names another version than `versions.lock` fails. A secret fails. A recording that still holds a token, an account id, or the mail address fails. | `make check`, from M1, and the gate |
| Instruction files and checks | A changed instruction file is refused unless `may_change` lists it, and is not loaded by the judging run. Checks are read from the database. | Temporary repositories, `FakeHarness` |
| Pause all, and the disk guard | No run starts, clocks wait, and Resume continues. The guard cleans at 85% and stops at 95%. | `FakeHarness`, a small scratch disk |
